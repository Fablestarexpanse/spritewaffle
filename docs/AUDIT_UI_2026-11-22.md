# Workspace and control audit

Audited from `ec6f5f9`. The source inventory contains 209 button and disclosure declarations.
The baseline Chromium sweep captured 87 surface and viewport combinations. The revised
interface captured 100 combinations and 3,532 rendered control observations, including
repetitions across views. The primary widths were 1440, 800, and 390 CSS pixels. Appearance,
New asset, job settings, and Tileset also ran at 390 px with Light and 150% interface scale.

## Findings and fixes

| Finding | Effect on the workflow | Fix and verification |
| --- | --- | --- |
| Project style, palette, and references were inside Appearance. | Finding project data required opening an unrelated preferences dialog. | The header **Project** menu has a style guide, master palette, reference library, and motion library. The first three passed save or edit scenarios. The menu dismissed with Escape and restored keyboard focus at all three widths. |
| Home had no control from inside a job. New lived inside the job browser. | A collapsed job browser hid job creation, and switching to a Home quick start was indirect. | The wordmark returns Home. **New asset** stays in the header. On narrow screens **Jobs** opens a transient browser that closes when a job is chosen. |
| Grouping the sidebar omitted Terrain. A list update reopened closed groups. | A tileset could disappear entirely in the grouped view. Polling disturbed the reader's place. | Added the Terrain group, kept disclosure state and focus when the list updates, and labelled the sort and filters. Chromium selected a Tileset from the grouped list at each width. |
| Job configuration and Archive competed with stage controls. | The top of each job looked like a settings form before any stage content. | Stage tabs sit directly below the job identity and common workflow actions. Profile, art style, prompts, camera, style checks, and archive live in **Job settings**. The profile-size action has its own button. |
| The queue had no close action in its own pane and rebuilt tasks on each poll. | Keyboard focus on Cancel was lost even when the queue data stayed the same. | Added Close and Escape, focus return, and stable task rows when their data is unchanged. Queue filters announce the selected option. |
| Character and showcase export could be offered without the required media. | The main action could only produce an avoidable error on an empty job. | Disable each action until the appropriate frames or facings exist. The character button responds to the selected frame set. |
| Five source paths put buttons inside links. | Playback, downloads, and viewer navigation had redundant interactive markup. | Each path now has one link, styled as an action where appropriate. Shared work dialogs also label themselves from their heading. [HTML link content model](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-a-element) |
| Tileset animation, objects, and map export sat far below the import controls. | A user had to scroll past several tools to find the desired task. | Added labelled shortcuts that scroll to and focus the section, and open Map objects when needed. The desktop layout gives the map more width. Narrow layouts use a two-column shortcut group and a compact Status disclosure. |

## Workflow coverage

| Surface | Checked |
| --- | --- |
| Home and job browser | Home link, global New asset, search and filter placement, group expansion, Tileset discovery, responsive sidebar closing |
| Project and Appearance | Menu order, keyboard dismissal and focus return, Light and enlarged text, existing colour and brand preferences, style and palette edits, reference upload, filter, archive, and restore |
| Queue | Open, close, filter placement, active task visibility, focus during a poll, and keyboard return to the launcher |
| Character, base body, animal, item | Anchor and facings layout, image viewer, item front and back, review state, and available next actions |
| Animation tools | Motion-library location, action-card detail, timeline, QA links, frame repair, pixel editing, playback and export paths |
| Character and item export | Export and freshness controls, empty-job gating, existing local Aseprite workflows |
| Effect and prop | Layout of effect setup, attachment entry paths, sprite-stack method selector and rebuild affordances |
| Tileset and maps | Sheet import, animation preview, terrain and map shortcuts, saved-map controls, object templates, map export, and Tiled round trips |

No horizontal overflow appeared in the inspected regions. Separate browser runs changed
project settings, edited pixels and frames, and exported disposable artwork using the local
processing paths. This audit combined a source inventory with representative runtime
states. Live model inference, mobile touch, assistive technology, and every alternate
error state remain outside the verified scope.

The remaining layout work is concentrated in long, conditional generation forms and
stage-specific dialog variants. A future pass should cover those while a real queue is
running, and measure keyboard and touch targets in the densest editor settings.
