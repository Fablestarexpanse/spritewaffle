Verified: LDtk 1.5.3 opened the export (window "map @ South_meadow"; [UNSAVED] on load, likely its tile pixel cache being rebuilt, not inspected because screen access was declined), and the file has 0 problems against LDtk's official 1.5.3 JSON schema (required fields and types over 29 definitions; the checker caught 2 of 2 injected errors). Found on the way: the UI kept Prepare map ZIP disabled while any cell was unresolved even with allow-empty ticked, so allow_empty was unreachable from the UI; fixed and checked in the browser (7 empty cells exported).
- 2026-11-26 Tile weight (roadmap: Tiled probability per texture variant). Stored as tile_probability {tile: weight} next to tile_properties (validated on read, kept on re-import of the same sheet, part of the export freshness snapshot), 0..1000 with 1 = normal (not stored), 0 = never at random; exported as "probability" on the tile in tileset.tsj and tileset.json. Set from the tileset panel (Weight box), CLI `tileset weight`, HTTP /tileset/probability, MCP tileset weight. Checked in the app after a restart (the server has no auto-reload: the new route 404ed on the old process). Not checked in Tiled itself (the portable Tiled was deleted after the collision check); probability is a standard tile field in the TSJ format. SpriteWaffle's own map painter still uses one tile per corner pattern.
- 2026-11-26 Map variant mixing. terrain.preview(weights=...) picks among all tiles with the same corner tuple per cell by tile weight (tile_probability; default 1, 0 = never unless nothing else); the pick is sha256 of "x,y" scaled by total weight, so preview, save and export agree and re-exports are identical. Opt-in per map (map record "mix": true; native map.json "mix_variants"); without it every corner pattern keeps its first tile, so maps saved before export unchanged (AGENTS: additive). Measured on a 32 x 32 grass field with weights 1 / 0 / 3: the weight-0 tile never appears and the 3:1 ratio lands in 2.4-3.8. Checked in the app: three greens mixed in the preview, saved with mix true.
- 2026-11-26 Texture lighting maps. texture.surface_maps: height = luminance, one wrapped 3x3 blur, stretched to 0-255; normal = OpenGL (green up) from wrapped central differences x strength (default 2). Every lookup uses np.roll, so the maps of a shifted tile are the shifted maps (tested): they tile exactly like the colour map. No model, no render; opt-in (surface_maps, default off) so existing exports are unchanged. Real run on archived cobble px32 and dirt painted128: 2x2 repeats show no seams, cobble mortar reads as sunken, both shade differently under two light directions (subtle on dirt). Known limit: colour is not depth, dark detail on a light surface reads as low. Not loaded in Godot or Unity yet.
- 2026-11-26 Map size. terrain.MAX_SIDE 32 -> 64 (no measured reason for 32 was logged; the gamedev audit listed it as a gap). The map panel had no size control at all (new maps fixed at 8 x 6; only CLI/MCP could change size), so it gains Size (w x h) + Resize: corners copied where they fit, overrides and objects re-indexed to the new row length, anything outside dropped after a confirm. Checked in the app: 8x6 fill kept when grown to 40x30, 70 refused, 64x64 fill = 4096 cells, canvas 2560 px scaled to the panel (cells ~6 px on screen: use the Cell box to target one). Tiled and LDtk export at 64x64 tested.
- 2026-11-26 LDtk entities for map objects. map.ldtk gains an "Objects" Entities layer (only when the map has objects, so object-free exports are unchanged): one EntityDef per object kind (identifier from kind, capitalised), renderMode Tile with the current state's tile, pivot 0,0, fields name / state / states (JSON) / spritewaffle_id / spritewaffle_template as F_String and solid as F_Bool; layout copied from LDtk 1.5.3's bundled Entities.ldtk sample (fetched from the deepnight/ldtk repo at v1.5.3 with the schema). Unique uids, nextUid above them. Checked: 0 problems against the official 1.5.3 schema including enum values. Not opened in the LDtk app this time (it was deleted after the first check).
